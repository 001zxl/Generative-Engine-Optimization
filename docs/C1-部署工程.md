# C1 部署工程 —— 已实现 / 未实现

对应方案第 3 节 C1。基准提交 `77744ab`。**按用户要求：只交付工程产物，未实际公网部署。**

## 已实现

### 1. 配置守卫分两个阶段

`scripts/preflight.ts build|runtime`（不传参数 = 两者都查，本地 `pnpm build` / `pnpm start` 行为不变）

| 阶段 | 校验什么 | 为什么这样分 |
|---|---|---|
| `build` | `APP_BASE_URL` / `SITE_NAME` / `CONTACT_EMAIL` | 静态预渲染页面（`/methods`、`/tools/*`）在构建期读取它们并写进 HTML；构建时错了整批产物都得重做。**此阶段不读也不要求任何密钥** |
| `runtime` | `CONSOLE_PASSWORD` / `AUTH_SECRET` / `DATABASE_PATH` | 密钥进入构建环境会被写进镜像层，任何拿到镜像的人都能翻出来 |

### 2. 容器化

- `deploy/Dockerfile`：三段构建（deps → builder → runner）；**非 root**（uid 10001）运行；数据库目录 `/data` 持久卷；健康检查打 `/api/health`；构建参数只有三个公开配置
- `deploy/entrypoint.sh`：启动前先跑运行期校验，失败即退出（`set -e`）；迁移改为按需开关
- `deploy/compose.yaml`：`app` 不发布端口（仅内部 `expose 3000`），只有 `caddy` 暴露 80/443；数据库在命名卷；`ALLOW_INSECURE_DEFAULTS` 与 `EXTRA_TRUSTED_CIDRS` 在公网环境强制为空
- `deploy/Caddyfile`：终止 TLS、反代、传真实客户端 IP（登录节流依赖它）

### 3. 备份与恢复演练（真跑过）

- `deploy/backup.sh`：用 `VACUUM INTO` 生成**一致性副本**（应用写入时直接 `cp` 会拿到撕裂快照），随后校验表数量、工作区、外键孤儿，输出 `.sha256`
- `deploy/restore.sh`：支持 `--drill`（恢复到临时目录 → 校验 `integrity_check` 与外键 → 清理）；恢复模式**拒绝覆盖已存在的文件**
- `deploy/db-tool.mjs`：独立小工具，避免 SQL 单引号与 shell 单引号互相截断

### 4. CI（`.github/workflows/ci.yml`）

四个作业：`verify`（分阶段配置校验 → 类型检查 → 单测 → 构建 → 依赖审计）、
`e2e`（起夹具服务 → 门店链路 / 内容渲染 / 发布门槛 / 公开页，且断言 `pilot:false`）、
`image`（构建镜像 + 断言镜像运行环境里没有密钥变量）、
`backup-drill`（准备有数据的库 → 备份 → 恢复演练 → 迁移幂等跑三遍）。

## 顺带修掉的两个真实风险

1. **`.env.production` 没有被 gitignore。** 部署文档要求把运营台口令与 `AUTH_SECRET`
   放进这个文件，而 `.gitignore` 只忽略了 `.env` 与 `.env.local` —— 按文档操作会把密钥提交上去。
   已改为 `.env` + `.env.*` 通配（保留 `!.env.example`），并确认历史提交里只有 `.env.example`。
2. **没有 `.dockerignore`，而 Dockerfile 用 `COPY . .`。** 实测构建上下文会包含
   `.env`（含口令）、`data/`（5.1MB 真实数据库）、`.git`、843MB `node_modules`。
   已新增排除清单，并用测试锁住：环境文件、数据库、`.git`、依赖目录必须被排除，
   且 `Dockerfile` 里不得出现任何密钥的 `ARG`/`ENV`。
