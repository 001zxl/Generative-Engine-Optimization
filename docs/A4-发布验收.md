# A4 发布验收 —— 已实现 / 未实现

对应方案第 3 节 A4。基准提交 `938d353`。

## 已实现

### 1. robots：具名爬虫组不再放开运营台

原实现给检索型与训练型爬虫各写了一个 `Allow: /` 组。robots.txt 的语义是
**具名 user-agent 组覆盖 `*` 组，而不是与之合并** —— 于是
`/console`、`/api/`、`/r/` 对 Googlebot、OAI-SearchBot、GPTBot 等实际是放开的。

现在三组规则带完全相同的 allow/disallow，规则数据抽到
`src/lib/robots-config.ts`（纯数据、可单测），`src/app/robots.ts` 只补 sitemap 与 host。

### 2. 发布后门槛分开记录（六项）

`checkPublishReadiness()` 逐项产出，不再合并成一句"页面正常"：

| 门槛 | 判什么 | 不通过的后果 |
|---|---|---|
| `http` | HTTP 状态码 | 抓取方拿不到页面 |
| `readable` | 正文长度（200 也可能空壳） | 抓到的是空壳，正文无法被引用 |
| `canonical` | 声明了且指向本页 | 同一内容可能被当成多个页面 |
| `robots` | 关键 AI 抓取方未被拦 | 被拦的抓取方完全看不到这页 |
| `sitemap` | robots 声明的 sitemap 或 `/sitemap.xml` 含该 URL | 搜索引擎可能发现不了这页 |
| `structuredData` | 有可解析的 JSON-LD 且带 `@type` | 抓取方难以确认页面主题与实体 |

分层判定：`ok`（全过，严格）、`reachable`（HTTP+正文+robots）、
`discoverable`（sitemap）、`wellFormed`（canonical+结构化数据）。
逐项结果落库到 `publication_checks.gates_json`，带检查时间。

### 3. 四项状态分开呈现

`src/lib/publication-status.ts`，发布页逐条显示：

| 状态 | 依据 | 能否自行断言 |
|---|---|---|
| 已发布 | 我们的发布记录与 URL | 能 |
| 可抓取 | 我们自己执行的门槛检查 | 能 |
| 已收录 | 搜索引擎后台数据 | **不能 → 永远是"未知"** |
| 被 AI 引用 | 采样到的回答里是否引用了该 URL | 只有命中才能写"是"，否则"未知" |

关键规则：**任何一步都不由前一步推断**。"页面可抓取"不推出"已收录"；
"发布了内容"不推出"被 AI 引用"；有样本但未命中时写"未观察到"而不是"否"
（样本未必覆盖该页主题）。

### 4. 第三态「未检查」

SSRF 防护会拒绝抓取本机/内网地址。这时报"未通过"是假阴性 ——
本地开发会永远是红的，久而久之没人再看这个检查。因此门槛有第三态
`not_checked`，`reachable` 为 `null`，状态显示为"未检查"并说明原因。

判定方式是**先抓再分类**，而不是事先按主机名短路：短路会让
`EXTRA_TRUSTED_CIDRS` 逃生口失效，本地永远无法验证真实门槛。

## 未实现（明确不承诺）

- 不接入搜索引擎/地图后台，「已收录」只能人工回填，本站不猜
- 不做关键词排名跟踪（方案未要求，且易被当成排名承诺）
- 不做页面级访问统计
- 「被 AI 引用」只比对 URL，不做"提到品牌但未给链接"的判定
  （那属于 B3 的三类问题分开报告）
