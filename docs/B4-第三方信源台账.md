# B4 第三方信源台账 —— 已实现 / 未实现

对应方案第 3 节 B4。基准提交 `6e83431`。

## 已实现

### 1. 独立台账表（不复用 publication_checks）

`external_sources` 记录：归属品牌/门店、支持的事实、平台、公开 URL、标题、内容主题、
来源性质、发布日期、上次核对时间与结果、冲突说明。

为什么不复用 `publication_checks`：那张表记的是"我们自己发出去的内容现在能不能访问"，
这张表记的是**别人写的、能给我们背书的外部页面**。混在一起会产生一个很危险的混淆 ——
把自家发的文章当成第三方报道，那正是这类产品最容易被戳穿的地方。

### 2. 三类来源性质，且不得把自发文章称为独立测评

| 性质 | 含义 | 可用说法 |
|---|---|---|
| `owned` 自有内容 | 我们自己或客户自己发布 | 不得称独立/第三方 |
| `authorized` 客户授权渠道 | 客户有权发布但非自有（投放页、平台商家主页、授权转载） | 不得称独立/第三方 |
| `independent` 独立第三方 | 与客户无发布关系的第三方所写 | 可用"独立测评"等 |

`detectIndependenceMislabel()` 检查标题、主题与备注里的措辞，
命中「独立测评 / 第三方报道 / 权威认证 / 客观评测」等说法即判为**阻断**。
只看字面，不做语义判断 —— 措辞规则本就该是硬性的。

### 3. 失效与冲突检测

- **核对可用性**：真实抓取目标页面（走 `fetch-page` 的 SSRF 防护与 DNS 固定），
  判定 `ok` / `mismatch`（页面在但找不到标题关键词，内容已变）/ `dead`（404/410）/
  `blocked`（登录墙或反爬，无法自动核对）
- **超期提示**：超过 90 天未核对提示重新核对
- **冲突标记**：注明与哪条来源冲突及说明；有冲突时该事实的结论优先判为 `conflicting`
- URL 走与发布模块同一套白名单；**同一 URL 不重复登记**，否则一篇文章会被当成两次独立背书

### 4. 报告口径：只列仍可访问的来源

`claimSourceSummaries()` 给出每条已批准事实的来源支持情况，四种结论：

| 结论 | 含义 |
|---|---|
| `supported` 有独立来源 | 有独立第三方来源仍可访问 |
| `only_self` 仅自有来源 | 只有自有/授权来源 —— 可以说明"我们这样介绍"，**不能**声称"第三方已证实" |
| `no_source` 无可用来源 | 没有仍可访问的来源，这条陈述目前无据可查 |
| `conflicting` 来源冲突 | 需人工判断后才能对外使用 |

失效与内容不符的来源**不进入可用清单**，只在"不可用"里列出并给出原因。

### 5. 运营台

`/console/sources`（导航「3b · 第三方信源」）：事实的来源支持情况、
来源明细（含逐条问题清单）、登记表单、核对可用性、标记冲突、删除。

## 未实现（明确不承诺）

- 不做自动发现：新出现的第三方提及需要人工登记或另做监测，首版不抓全网
- 不做页面快照存档：只记录 URL 与核对结论，不代管第三方内容副本（版权与存储成本）
- 不做内容差异比对：`mismatch` 只判断"标题关键词还在不在"，不做全文比对
- 不做百度/微信等有反爬的平台自动核对：这类平台一律走人工核对
