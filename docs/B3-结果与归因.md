# B3 结果与归因 —— 已实现 / 未实现

对应方案第 3 节 B3。基准提交 `29805cb`。

## 已实现

### 1. 三类结果分开展示

`src/lib/category-metrics.ts`，按问题类目分块：

| 块 | 回答什么问题 | 计入推荐判断 |
|---|---|---|
| 认知题 | 模型对这个品牌的描述准不准 | 否 |
| 推荐题 | 能不能被推荐（最接近真实提问） | 是 |
| 场景题 | 模型在约束条件下的选择 | 是 |
| 引用来源 | 模型引用谁的内容来解释你 | — |
| 未分类 | 单独成块，**不并入任何一类** | — |

每块给出：**分子 / 分母**（不是只有一个比率）、首位率、竞品出现率、事实错误、口径说明。
指标计算**复用 `computeMetrics`**，不另写一套 —— 口径只能有一份。

为什么必须分开：认知题里出现品牌是必然的，混算会把提及率抬高。
验收脚本用同一批样本验证了这一点：推荐题 0/2，混算则变成 3/5。

### 2. 竞品出现

每个类目块给出竞品出现率（分子/分母）与各竞品被提到的样本数排行。
竞品可从 `mentions` 里兜底识别（非目标实体）。一条竞品都没出现时提示
"可能没配竞品清单"。

### 3. 引用来源单独成块

自有来源引用率（分子/分母）+ 按域名排行（自有优先）。
明确区分"被提及"与"被引用"：模型可能提到你，却引用别人的页面来解释你。

### 4. 按类目落库

`evaluateScope()` 现在为每个类目单独写 `metric_snapshots`，
`dimension_json` 带 `category` 与 `countsTowardRecommendation`，
并新增 `competitor_mention_rate` 指标。报告与复测对比都按同一维度取数。

报告取数走 `repo-eval-samples.ts`：**只读 `evaluation_results`，不重算** ——
报告必须复现评测当时的结论，否则前后对比的口径会变。

### 5. 线索归因

`src/lib/lead-attribution.ts`：渠道、落地页、utm、引荐域名、关联内容、关联门店、客户自述来源。

渠道判定优先级：`utm_medium` > `source` 前缀（结果页 / 门店页 / 品牌页 / 知识页）> 引荐域名 > **未知**。
每条给出判定依据（`channelBasis`），便于人工核对。

**缺失一律保持「未知」，不给默认值。** 把没有 utm 的线索默默记成 direct，
报表上会凭空多出一批"直接访问"，而且再也分不清"真是直接访问"与"我们没采到"。
界面上逐项列出「未知项」，不留空白。

## 未实现（明确不承诺）

- 不做多触点加权归因模型：权重表没有行业数据支撑，只会产出看似精确、实则不可验证的数字
  （现有三种口径并列展示：First Touch / Last Non-direct / 自述来源）
- 不做事实错误的按类目重新判定：事实错误来自 `evaluator='facts'`，按类目归并的是同一批判定结果
- 不做图表可视化：报告用表格给出分子/分母与口径，可核对优先于好看
