# A3 结构化数据 —— 已实现 / 未实现

对应方案第 3 节 A3。基准提交 `3f77ac7`。

## 已实现

| 项 | 落地位置 | 说明 |
|---|---|---|
| JSON-LD 生成器 | `src/lib/jsonld.ts` | 门店 `Restaurant`/`LocalBusiness`、品牌 `Organization`、文章 `Article` |
| 类型选择 | `localBusinessType()` | 餐饮类用 `Restaurant`，其他用 `LocalBusiness`；不硬套 |
| 只写可见内容 | `compact()` + `checkJsonLdConsistency()` | 空值字段直接不输出；关键字段必须在页面文字或链接里出现 |
| 不编造字段 | 单元测试守住 | 无评分、无奖项、无 review；没有价格就不写 `priceRange` |
| 序列化安全 | `serializeJsonLd()` | 转义 `<`，防止内容里的 `</script>` 提前闭合标签 |
| 页面接入 | 门店页 / 品牌页 / 知识页 | 知识页原有的手写 `articleJsonLd` 已统一到本模块（此前缺转义） |

## 未实现（明确不承诺）

- 不写 `openingHoursSpecification`：营业时间是「每日 09:00-21:30」这样的文本，
  无法可靠拆成 schema 要求的逐日结构。宁可只写 `openingHours` 文本，也不写错结构
- 不写 `aggregateRating` / `review` / `award`：本平台不采集这些数据，方案也明确规定不得补造
- 不写 `geo` 坐标：门店经纬度尚未经授权核验，A2 阶段刻意留空
- 不做结构化数据的富结果测试（Rich Results Test 需外部服务）

## 顺带修掉的一个真实问题

`addressCountry: "CN"` 曾是硬编码。页面上根本没有「CN」字样 ——
既违反"只写页面可见内容"的规则，也让地址为空时仍输出一个只有国家的无用
`PostalAddress`。已移除，并在测试里加了断言：结构化数据不得出现页面上没有的字样。

`@type` / `name` / `telephone` / `address.streetAddress` 与页面内容，
并断言不含评分、奖项与页面上没有的国家代码。

URL 类字段出现在属性里而不是文字里，只查文本会误报。
