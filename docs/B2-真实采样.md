# B2 真实采样 —— 已实现 / 未实现

对应方案第 3 节 B2。基准提交 `bb2c570`。

## 已实现

### 1. 消费者界面人工采样入口

`sampling.ts` 的 `saveManualObservation()` 要求并保存：

| 项 | 要求 |
|---|---|
| 回答原文 | 必须，1–200000 字 |
| 模型版本 | 必须（平台界面显示值） |
| 采集时间 | 必须且**带时区** |
| 平台分享链接 / 截图路径 | 至少其一，否则样本标为「不可追溯」 |
| 引用网址 | 最多 50 条，仅接受无账号密码的 HTTP(S) |
| 采样人员 | 记录谁采的；缺凭据时第一个要问的就是这个 |

同一任务重复提交是**幂等**的：返回原样本，不产生重复记录。

### 2. 官方 API 单独成组

`sample_provenance.evidence_kind` 区分 `manual_ui` / `official_api` / `fixture`。
证据分组按 **协议 × 界面 × 定位方式 × 联网状态** 四维切分，不同组不合并 ——
消费者界面与官方 API、真实定位与只写地名，拿到的回答不是一回事。

### 3. 不得用本平台生成的模拟回答充当外部结果

这条做在**数据库层**：`evidence_kind` 上的 CHECK 约束只允许
`manual_ui / official_api / fixture`，`synthetic` 根本写不进去。
比在应用层过滤更可靠 —— 不依赖每个写入路径都记得检查。
验收脚本直接尝试写入 `synthetic` 并断言被拒。

### 4. 证据不足 → 报告标「不可判定」

`sample-evidence.ts` 两级判断：

- **单条**：来源不是外部观察 / 没有原文 / 没有模型版本 / 没有采集时间 → 阻断，不计入
- **分组**：每组最少 10 条可信样本；带链接或截图凭证的比例不得低于 **80%**；
  未绑定协议单独提示

判定分三档：`sufficient` 证据充分 / `insufficient` 样本量不足 / `not_judgeable` 不可判定。
整体结论**取最差的一组** —— 不因为多数组达标就放松。效果报告页顶部显示该判定与分组明细。

阈值为什么是 80% 而不是 50%：这份报告是交给客户的。
"一半样本没有可复核凭据"支撑不起对外结论。

### 5. 可追溯性

每条指标都能回到原始回答：`getSample(sampleId)` 取回原文，
`answerForExtraction()` 把原文与记录的引用网址一并交给抽取器（不改动原文）。

## 未实现（明确不承诺）

- 不做截图内容识别与存档：只记录路径/链接，不代管文件
- 不做平台账号自动化：消费者界面采样必须人工完成（合规与稳定性原因）
- 不做反爬绕过
- 「被 AI 引用」只按 URL 精确匹配，不做"提到品牌但没给链接"的判定（属 B3）

## 顺带修掉一个真实缺陷

**人工采样路径的样本丢失了定位方式与联网标记。**
`sampling.ts` 插入 `response_samples` 时没有继承批次的
`location_mode` / `anchor_id` / `web_search`，样本一律落成「未标注 / 不联网」。
后果是人工采样的批次在报告里被归到「未标注定位」，
与"仅在问题文字里写地点"的采样混为一谈 —— 恰好破坏了
「两种采样方式必须分开标记」这条核心规则。已改为从批次继承（含模型版本）。
