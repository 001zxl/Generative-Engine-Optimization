
## 5. 完整操作流程（七步）

侧边栏的编号就是操作顺序。

### 第 0 步（可选）：先用公开工具做一次诊断

**目的**：在动手建库之前，先看清这个站点的 AI 可发现性到底缺什么。

打开 http://localhost:3100，输入网址，例如：

```
www.pailian-aluminium.com
```

会得到一份带证据的结果页，包含两块：

| 工具 | 检查什么 | 典型结论 |
|---|---|---|
| AI 爬虫可访问检查 | robots.txt 是否放行检索型 AI 爬虫、页面能否抓取、正文是否依赖 JS | 「0 严重问题」说明爬虫层没毛病 |
| 内容可引用性检查 | 8 个维度：是否直接回答问题、事实密度、作者时效、FAQ、结构可切分… | **通常只有 30–40 分** —— 真正的缺口在这 |

> **实测参考**：pailian-aluminium.com 的爬虫层 0 严重问题，但内容可引用性只有 31/100。
> 三个维度是 0 分：直接回答问题、作者与时效、FAQ 覆盖。
> 它的首页 26 个 `<p>` 里 25 个是导航项与标题，**没有一句可被 AI 摘出来引用的话**。

**这一步的意义**：它证明"能抓到"和"值得引用"是两件事。诊断结论要卖的是后者。

---

### 第 1 步：品牌与竞品

**地址**：http://localhost:3100/console/brands

要做的三件事：

1. **品牌名 + 品牌域名** —— 域名决定"哪些引用算自有域"
2. **别名** —— 品牌简称、英文变体、中文名、常见错误拼写
   > 别名不全会让提及率**系统性偏低**。比如品牌叫 `Pailian Aluminium`，
   > 如果 AI 回答里写的是 `Pailian`，而你只录了全称，这次提及就不算数。
3. **竞品** —— 用于计算 Share of Voice（你和竞品谁的注意力占比高）

**种子数据已含**：`Pailian Aluminium` + 4 个别名 + 竞品 `HXM Aluminum`。可直接跳到第 2 步。

---

### 第 2 步：问题库

**地址**：http://localhost:3100/console/questions

**关键机制：冻结（Freeze）**

- 问题集在 `draft` 状态可以随意增删
- 点「冻结此版本」后，**问题不可再编辑**，只能新建一个问题集
- 为什么这么设计：GEO 的指标全部建立在"同一批问题反复采样"上。如果问题每轮都变，
  就无法证明可见度真的变了 —— 冻结不是麻烦，是让结论成立的前提

**写问题的要点**：

- 写**客户真实会问 AI 的完整问句**，不是关键词
  - ✅ `Which Chinese aluminum profile manufacturers can handle a 500-unit trial order?`
  - ❌ `aluminum profile manufacturer China`
- 覆盖不同漏斗阶段：认知 / 比较 / 风险 / 交易
- **不要超过 20 条**。每条要 × 平台数 × 重复次数，问题越多人工成本越高

**种子数据已含**：10 条已冻结的真实买家问题（英文 9 条 + 中文 1 条）。

---

### 第 3 步：事实与证据

**地址**：http://localhost:3100/console/claims

**作用有两个**：

1. 事实一致性评估的**比对基准** —— AI 说错了什么，要有权威版本对照
2. 内容生产的**约束来源** —— 未批准的事实不应写进对外内容

**操作**：

- 新增 Claim（`claim key` 是机器标识，如 `moq`、`lead_time`）
- 给每条 Claim 绑定证据（标题 + URL + **证据等级**）
- 点「批准」—— **只有已批准的 Claim 参与一致性比对**
- 可配置「禁用表述」（如"100% 保证"）

**证据等级要如实标注**：

| 等级 | 含义 |
|---|---|
| 第三方 | 媒体 / 协会 / 评测机构的报道 |
| 官方 | 认证证书 / 检测报告 / 国家标准 |
| 审计 | 审计报告 / 年报 |
| **自述** | **仅官网自己说** |

> 种子数据里 9 条事实**全部标为「自述」级**，并把原始 URL 放在证据里 ——
> 因为那确实只是官网自己的说法。**如实标注等级，客户才能判断该信多少。**

**写好事实的技巧**：陈述里带上具体数值（如"500 件起订"），
事实一致性评估依赖数值比对；纯形容词（"品质卓越"）无法自动核验。

### 第 4 步：多平台采样 ← **本手册的重点**

**地址**：http://localhost:3100/console/sampling

当前批次：`Pailian · 2026-09 基线（真实站点试点）`
直达链接：**http://localhost:3100/console/sampling?run=run_s_f0657d0db067426b9a5ffc6d**

待采 20 条 = 10 个问题 × 2 个平台（ChatGPT 10 条 / 通义千问 10 条）。

#### 4.1 为什么必须人工做

系统的 `sampling_mode` 字段把采样方式分成 `manual_ui` 与 `official_api`，**两者不能混算**。原因：

- GEO 测的是「AI **搜索产品**对买家说了什么」，包含 **检索 → 排序 → 引用** 三个环节
- 官方 API 的补全**不含检索**：没有引用来源可测（自有域引用率恒为 0），
  品牌提及只反映训练数据，**与"买家能不能找到你"无关**
- 国内平台（豆包/千问/元宝）基本没有合规的公开检索 API

**所以人工粘贴不是绕路，是唯一正确的方法。**

#### 4.2 逐条操作

对每一条待采任务：

1. 打开 **ChatGPT**（chat.openai.com）或 **通义千问**（tongyi.aliyun.com）
2. **确认联网检索已开启**（ChatGPT 需要手动点搜索按钮；千问默认开）
3. **原样粘贴**问题
4. **完整复制整个回答，包括末尾的引用来源链接**

> ⚠️ **三条硬要求**
> - **不要摘要、不要改写** —— 引用抽取依赖原文里的 URL，摘要会让引用率变成 0
> - **平台没给引用来源就如实留空** —— "这个平台不给引用"本身就是有价值的数据
> - **两个平台分别做** —— 不要混在一起

5. 粘到运营台对应任务的输入框，可选填模型版本 → 点「保存回答」

页面上一次显示前 12 条待采任务；剩余用 CSV 导入更快。

#### 4.3 CSV 批量导入（推荐）

页面下半部分有「CSV 批量导入」，表头：

```csv
question,engine,answer
Which Chinese aluminum profile manufacturers can handle a 500-unit trial order?,ChatGPT,"我推荐以下几家的…
（这里放完整回答，含 https://xxx.com 这样的引用链接）"
```

- `answer` 里含逗号或换行时，必须用**双引号包裹**
- 可选列：`region`、`model_version`、`collected_at`
- 问题文本必须与该批次问题集里的**完全一致**，否则该行会被拒绝并报错（这是防错设计）

#### 4.4 20 个待采问题

**ChatGPT** 与 **通义千问** 各问一遍：

```
1.  Which Chinese aluminum profile manufacturers can handle a 500-unit trial order?
2.  Who are the reliable aluminum extrusion suppliers in China for small MOQ orders?
3.  What is a typical MOQ for custom aluminum extrusion from Chinese factories?
4.  Which Chinese suppliers offer both aluminum extrusion and CNC machining in one place?
5.  How do I verify that a Chinese aluminum profile factory is ISO 9001 certified?
6.  What certifications should I check before ordering aluminum profiles from China?
7.  Which Chinese aluminum profile suppliers serve small and medium brands in Europe?
8.  How long does custom aluminum extrusion tooling take from a Chinese supplier?
9.  Who can supply anodized and wood-grain aluminum profiles with a low minimum order?
10. 铝型材厂的最小起订量一般是多少？交期多久？
```

#### 4.5 采集中要顺便观察的四件事

这四件事决定了这门生意成不成立，比指标数字重要：

1. **你愿不愿意手工做这 20 条？** 一个真实客户要 150 条（10 问 × 5 平台 × 3 次）时还成立吗？
2. **国内平台拿得到吗？** 豆包/千问要登录；有的平台根本不显示引用来源
3. **平台给出的引用源是什么？** 是行业媒体、目录站、还是竞品官网？这直接指导第 6 步该去哪发内容
4. **AI 有没有说错事实？** 对照第 3 步的事实库看

### 第 5 步：评估与指标

**地址**：http://localhost:3100/console/evaluation

1. 「采样批次」下拉框**默认已选中当前批次**（不要改成"全部样本"，除非你就想跨批次评估）
2. 点「运行评估」
3. 稍等几秒，四个指标出现

**四个指标的含义**：

| 指标 | 定义 | 怎么读 |
|---|---|---|
| **品牌提及率** | 提及目标品牌的有效样本数 ÷ 有效样本总数 | "100 个买家问题里，AI 提到你几次" |
| **首推率** | 被列为第一位的样本数 ÷ 可判断排名的样本数 | 最值钱 —— AI 说"首选是 X"时 X 是谁 |
| **Share of Voice** | 目标品牌提及次数 ÷ 全部被跟踪实体提及次数 | 相对竞品的注意力占比 |
| **自有域引用率** | 引用了你域名的样本数 ÷ 含可识别引用的样本数 | AI 是引用你官网，还是只引用第三方 |

**每条指标都带分子/分母与「计算口径」**，可点开核对。

**⚠️ 看到「无法计算」不是 bug**：

- 首推率无从判断 → 回答不是列表形式
- 自有域引用率无从计算 → 回答里没有任何可识别的引用来源

系统**刻意不把这种情况显示成 0%** —— 0 会被误读成"表现差"，而实际是"数据不足"。

**事实一致性**单独一栏：判定基于数值匹配的启发式算法，**一律标记为待人工复核，不作为结论直接展示**。

## 6. 本地门店 GEO（第二条链路：八步闭环）

前面第 5 章是**品牌级**链路（回答「这个品牌在 AI 里被提到吗」）。
这一章是**门店级**链路（回答「这家店会不会被推荐给附近的人」）。
两条链路共用采样与评估，但门店链路多一个维度：**位置**。

流程：

```
A 商家授权与门店建档 → B 地图资料核对 → C 按位置建立问题集
→ D 采集发布前基线 → E 补充证据并发布内容 → F 检查公网可访问性
→ G 原条件复测 → H 输出可见度与线索报告
```

### 6.1 两种定位方式：绝对不能混

这是整条链路最容易出错、也最容易被拿来忽悠人的地方。

| 定位方式 | 含义 | 能得出什么结论 |
|---|---|---|
| `device_location` 真实设备定位 | 采样设备真的位于某个锚点 | 可以判断「附近推荐」表现 |
| `question_text_only` 仅问题文字含地点 | 只是问题里写了「人民广场附近」 | 只能反映模型对文字的理解 |
| `unspecified` 未标注 | 没有记录定位信息 | 不能用于任何位置结论 |

**采样批次创建时就要选定，样本写入后不可修改。** 报告里两种方式分开成块展示，
永不合并平均 —— 合并会把「模型读懂了地名」当成「附近推荐有效」，这是虚假结论。

系统会在几个地方主动拦你：

- 报告里每种定位方式单独一块，混入其它模式的样本会被显式标红
- 只有 `device_location` 的块才会出现「可用于判断附近推荐表现」
- 批次默认值是 `unspecified`，**不是** `device_location` —— 没标注就得显示没标注

### 6.2 A · 门店档案

**地址**：http://localhost:3100/console/stores

1. 建门店：填店名（**带分店名**）、地址、城市、经纬度、品类、服务半径
2. 填营业时间：按周一到周日逐格填
3. 加门店事实：店名、电话、地址、营业时间等，每条都要有**来源链接**

事实的规矩：

- 一条事实必须有来源，且经过「核验」才可用于判断平台资料对不对
- 核验超过 **180 天**会标记「建议重新核验」
- 状态为「有争议」或「未核验」的事实不参与判断

> 店名归一化会**保留分店标识**。「星巴克（人民广场店）」和「星巴克（南京西路店）」
> 是两个不同的店，不会被当成同一个 —— 归一化太激进会导致「推荐错店」。

### 6.3 B · 地图资料核对

**地址**：http://localhost:3100/console/map-listings

1. 登记平台资料：选平台（Google Business / 高德 / 百度地图等），填 POI ID、认领状态
2. 保存快照：把**你在平台页面上看到的**店名/地址/电话/营业时间填进去
3. 系统自动比对，列出差异并分级：
   - **阻断级**：店名或地址不一致 —— 先修这个，否则后面的数据没意义
   - **警告级**：电话或营业时间不一致 —— 会导致客户打不通或白跑一趟
   - **提示级**：品类等其它差异
4. 人工在平台侧修正后，回来把差异标记为「已处理」并写处理说明

> ⚠️ **首版只做授权查询与人工修正，系统不会自动修改任何第三方平台资料。**
> 所有对接平台的写接口都涉及违反平台条款的风险，这一版刻意不做。

### 6.4 C · 位置采样：锚点与场景

**地址**：http://localhost:3100/console/geo-sampling

- **锚点**：测试时设备所在的位置（如「地铁站 2 号口」「某写字楼大堂」）
- **场景**：锚点 + 半径 + 时段 + 需求（如「晚餐时段、两人用餐」）
- 每个场景都要写「**为什么预期这家店应该被推荐**」——
  不写预期，后面就没法对照，报告只能给出一堆没有判断标准的数字

### 6.5 D–F · 采集基线 → 发布 → 检查可访问性

在**多平台采样**页（http://localhost:3100/console/sampling）建批次时：

- 「关联门店」选这家店
- 「定位方式」按第 6.1 节如实选择
- 「测试锚点」只在真实设备定位时选
- 「时段」选早/午/晚

采集方法见第 5 章第 4 步：**人工粘贴到消费者界面**，样本带分享链接与截图。

发布后在**发布与复测**页（http://localhost:3100/console/publishing）点「复测已发布 URL」，
系统会检查三项门槛，逐项显示通过与否：

| 门槛 | 检查什么 | 不过的后果 |
|---|---|---|
| 页面可公开抓取 | HTTP 状态 + 正文长度 | 登录墙、空白页、纯前端渲染 —— 抓取方看到的是空页 |
| robots.txt 未拦 AI 抓取方 | 逐个核对关键 AI 抓取方 | 被拦的抓取方完全看不到这页 |
| 站点地图已收录 | robots 声明的 sitemap 或 `/sitemap.xml` | 搜索引擎可能发现不了这页 |

> 注意：只屏蔽 `GPTBot`（纯训练爬虫）**不算**实质阻断，系统不会误报。
> 它喂的是训练语料，不影响检索与引用。

### 6.6 G–H · 原条件复测与效果报告

**地址**：http://localhost:3100/console/geo-report

复测要求**同门店、同定位方式、同问题集、同样本量级**。报告会展示：

- 四个指标的前后对比：品牌提及率、首位推荐率、声量份额、自有来源引用率
- **事实错误率**：AI 回答中与已核验事实冲突的比例
- 门店线索数（只算已回填门店归属的线索）

报告刻意遵守的规矩：

- **样本量不足不下方向判断**。基线或复测少于 5 条样本时，判定显示「不可比」，
  哪怕数字上差了 30 个百分点 —— 3 个样本的波动没有意义
- **没有提升就写没有提升**。复测低于基线时判定为「下降」，并给出
  「可能与内容改动无关（平台模型更新、时段、竞争变化）」的说明，不做因果主张
- 「无法判断」的事实判定**不计入错误率分母** —— 把判断不了当成判对了会低估错误率
- 报告页底部明示：**没有付费排名捷径，不承诺、也无法保证任何排名或推荐结果**

## 7. 排错

### 7.1 启动失败：配置被拒绝

```
[preflight] ✖ 拒绝启动：检测到不适用于生产环境的配置
  • APP_BASE_URL 指向本机地址…
  • CONTACT_EMAIL 仍是占位邮箱…
```

这是**刻意的守护**，不是 bug。本地以生产模式自测时，在 `.env` 加一行：

```ini
ALLOW_INSECURE_DEFAULTS=1
```

### 7.2 端口被占用

```
Error: listen EADDRINUSE: address already in use :::3100
```

```bash
lsof -ti:3100 | xargs kill -9
```

### 7.3 登录后又被踢回登录页

- 检查 `.env` 是否有 `CONSOLE_PASSWORD` 与 `AUTH_SECRET`（两者都必填，缺一即拒绝所有人）
- 改过 `.env` 后**必须重启服务**
- 连续失败 8 次会锁定 10 分钟

### 7.4 检查外部网址报「该域名解析到内网地址」

本机网络走透明代理，大量外网域名被解析到 `198.18.0.0/15`。`.env` 里的
`EXTRA_TRUSTED_CIDRS=198.18.0.0/15` 就是为此放行的。

- 若仍失败：确认该行存在并重启
- **正式部署请删除该行**（真正的内网地址在任何情况下都会被拒绝）

### 6.5 「检查请求过于频繁」

公开工具限流 **12 次 / 10 分钟 / IP**。等一会儿即可。这不是故障。

### 6.6 某个站点抓取偶发失败

首次请求可能 12 秒超时（透明代理首包抖动）。**重试一次**。

### 6.7 评估点下去没反应 / 指标不出现

1. 确认该批次**已有样本**（采样页显示"已采 N"，N > 0）
2. 确认第 1 步的**品牌与别名**已建立 —— 没有品牌，系统不知道"什么算提到了我们"
3. 确认第 3 步**至少批准了一条事实** —— 否则事实一致性环节不产出结论

### 6.8 想清空重来

```bash
pnpm db:reset     # 删除 data/ 目录（含所有线索与采样）
pnpm seed         # 重新写入演示数据
```

## 9. 当前能力边界（如实列出）

### 已实现

- 两个免费公开工具（纯规则，零 AI 调用，单次成本 0）
- 可分享结果页（默认不被索引，持链接可访问）
- 线索闭环（结果页留资 → 运营台可见）
- 核心链路七模块：品牌 / 问题库（含冻结）/ 事实库 / 采样 / 评估 / 内容 / 归因
- 本地门店链路：门店档案 / 地图资料核对 / 位置化问题库 / 可信内容发布 / 地理采样与报告
- 发布后三项门槛检查（页面可抓取 / robots 未拦 AI 抓取方 / 站点地图已收录）
- 运营台访问控制（口令 + HMAC 签名会话）
- 生产配置守卫（占位配置拒绝启动）

### 未实现（不要以为是 bug）

| 缺什么 | 说明 |
|---|---|
| **官方 API 自动采样** | 接之前必须先解决"API 回答 ≠ 消费端回答"的口径问题 |
| **基线 vs 复测的并排对比视图** | 品牌级在「基线与复测」页；门店级在「效果报告」页 |
| **地图平台自动写回** | 首版刻意不做：自动改第三方资料有违反平台条款的风险，只做授权查询 + 人工修正 |
| **真实设备定位的自动采集** | 需要真实设备与平台合规接口。当前靠人工在真实设备上操作后回填，系统只负责记录与区分 |
| 内容自动扫描 | "内容里是否引用了未批准事实/禁用词"尚未自动检查 |
| 登录鉴权只有单口令 | 无用户表与角色权限（当前是单工作区单操作员场景） |
| 多实例部署 | `node:sqlite` + 内存限流只适用「单机 + 持久磁盘」。多副本需 PostgreSQL + 迁移系统 + Redis 限流 |

### 9.3 跑端到端测试时必须用夹具服务

端到端脚本会创建线索、门店、样本等真实数据。它们**绝不能跑在试点库上**。

系统为此加了两道闸：

1. `/api/health` 会自报 `pilot` 字段，标识当前连的是不是 `data/geo.db`
2. `scripts/e2e-check.py` 等脚本在写任何数据之前先查这个字段，是试点库就直接退出

正确做法：另起一个夹具服务

```bash
DATABASE_PATH=/tmp/fixture.db APP_BASE_URL=http://localhost:3101 \
  ALLOW_INSECURE_DEFAULTS=1 CONTACT_EMAIL=dev@example.org \
  CONSOLE_PASSWORD=fixture-pass AUTH_SECRET=fixture-secret-0123456789abcdef \
  npx next start -p 3101

pnpm run fixture:eval /tmp/fixture.db        # 准备夹具数据
pnpm run e2e:check -- http://localhost:3101  # 对着夹具跑
pnpm run e2e:local -- /tmp/fixture.db http://localhost:3101 fixture-pass
```

> 为什么这么强调：试点库里曾经堆着 19 条 `buyer@example-eu.com` 的假线索，
> 报表上看起来像「已经有 19 个客户」。假数据一旦混进对外报告就收不回来了。

另外，线索入口现在会拒绝 `example.com` / `.test` / `.invalid` 等保留域名 ——
这些域名永远收不到回复，属于测试数据而不是真实线索。

## 10. 两个必须理解的原理

### 10.1 为什么"能抓到"不等于"会被引用"

生成式引用的链路有两段，彼此独立：

| 环节 | 决定什么 | 检查工具 |
|---|---|---|
| **抓取与索引** | 检索型爬虫能否取到你的页面。取不到，你在任何 AI 答案里都不可能被引用 | 工具 A |
| **内容可引用性** | 取到之后，内容能否被**直接摘出来用** | 工具 B |

任何一段断裂，另一段的优化都不生效。**多数工厂站的缺口在第二段。**

### 10.2 为什么"豆包爬虫"不存在

国产 AI 助手大多**不自己抓网页**，而是复用母公司的搜索索引：

| AI 产品 | 真正的杠杆点 |
|---|---|
| 文心一言 / 百度 AI 搜索 | `Baiduspider` |
| 腾讯元宝 | `Sogou web spider` |
| 夸克 AI / 通义（部分场景） | `YisouSpider`（神马） |
| 通义千问 | `QwenBot` |
| 豆包 | `Bytespider`（**没有名为 Doubao 的爬虫**） |

所以你在服务器日志里搜不到"豆包爬虫"是正常的。**真正该维护的是搜索索引爬虫的抓取条件**，
而不是去屏蔽一个不存在的 token。
